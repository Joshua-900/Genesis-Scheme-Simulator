## Feature Spec: Multi-Turn Conversational RAG Page (`/chat`)

Generated by spec-expander | 2026-04-20

### Summary

A new conversational, multi-turn RAG interface served at `/chat`, parallel to the existing one-shot `/ask/static/sse_demo.html`. Users hold a persistent chat with the RAG system, with history, per-turn sources, and CFD observation. Built as a standalone subsystem — a new backend subpackage and a new frontend directory of ES modules — so the existing `/ask/stream` and sse_demo UI remain untouched. Retrieval uses LLM query-rewriting by default for conversational follow-ups; generation switches to Ollama's native `/api/chat` so history is a first-class concern, not a string hack.

### Rule Zero — Non-Negotiable

**Nothing existing breaks.** No edits to [rag_app/api/streaming_routes.py](vscode-webview://0lo17r9qvsne1l55u4vdg1vj0bd22tkf6p0vs3rke2vaf47agvr8/rag_app/api/streaming_routes.py), [rag_app/api/utils.py](vscode-webview://0lo17r9qvsne1l55u4vdg1vj0bd22tkf6p0vs3rke2vaf47agvr8/rag_app/api/utils.py) `make_prompt` signature, [rag_app/static/sse_demo.*](vscode-webview://0lo17r9qvsne1l55u4vdg1vj0bd22tkf6p0vs3rke2vaf47agvr8/rag_app/static/), [rag_app/static/sse_markdown.js](vscode-webview://0lo17r9qvsne1l55u4vdg1vj0bd22tkf6p0vs3rke2vaf47agvr8/rag_app/static/sse_markdown.js), or the guardrails module. The chat page adds; it does not modify. If a shared utility is needed, it is duplicated into the new subsystem rather than extracted (out-of-scope refactor). The existing `/ask/stream`, `/ask/sse_get`, `/ask/debug`, and `/ask/static/sse_demo.html` flows continue to work identically after this feature ships.

### Acceptance Criteria

**Frontend**

- [ ]  `/chat` loads a new page with chat-bubble transcript, composer (textarea + Send), sidebar (chat list + New Chat), and a collapsed Settings panel.
- [ ]  User can send a message; assistant response streams token-by-token into a new assistant bubble below.
- [ ]  Stop button aborts only the in-flight assistant turn; prior transcript and session_id persist; user can immediately send a new turn.
- [ ]  New Chat button shows a confirmation dialog before discarding the current chat, then mints a fresh `session_id` and clears the transcript.
- [ ]  Past chats appear in the sidebar; clicking one switches the active chat (transcript + settings restored).
- [ ]  All chats and their settings persist across page reloads via `localStorage`.
- [ ]  Assistant bubbles render Markdown; user bubbles render plain text.
- [ ]  Each assistant bubble exposes a **Copy** button (copies the assistant text) and a **Regenerate** button (discards and re-runs the last assistant turn).
- [ ]  Each assistant bubble has a collapsible `▸ Sources` section (retrieved chunks with scores) and `▸ Debug` section (prompt length, token counts, timings, rewrite output) populated from the stream's meta/debug events.
- [ ]  Settings panel shows a tight subset — Collection, Gen Model, Use CFD, Guardrail — with an "Advanced…" disclosure for the full set (mirrors sse_demo fields).
- [ ]  Settings are **per-chat**: each chat remembers its own; switching chats restores that chat's settings.
- [ ]  Retrieval-mode toggle in Settings: `rewrite` (default) or `raw`.
- [ ]  Home nav link and sse_demo header gain a "Chat" button pointing to `/chat`. _(These are additive additions to [rag_app/static/sse_demo.html](vscode-webview://0lo17r9qvsne1l55u4vdg1vj0bd22tkf6p0vs3rke2vaf47agvr8/rag_app/static/sse_demo.html) header — confirm with user before shipping; may be moved to Open Questions if modification of sse_demo.html violates Rule Zero.)_

**Backend**

- [ ]  New endpoint `POST /chat/stream` accepts a chat request (see Data Contract) and returns SSE.
- [ ]  New endpoint `POST /chat/debug` returns a non-streamed JSON debug blob for the current request (parity with `/ask/debug`).
- [ ]  Generation uses Ollama's `/api/chat` with `messages[]` (system, user, assistant turns).
- [ ]  Guardrail content is passed as the system message.
- [ ]  When `retrieval_mode="rewrite"` and history has ≥1 prior turn, a query-rewrite LLM call runs before embedding; the rewrite text is surfaced in the debug event.
- [ ]  When `retrieval_mode="raw"`, embedding uses the raw latest user turn only.
- [ ]  History trimming enforces a token budget (est. via char-count heuristic; configurable constant) and drops oldest turns first.
- [ ]  Each completed turn writes CFD observations tagged with the conversation's `session_id` (shared across all turns of that chat).
- [ ]  `/ask/stream`, `/ask/sse_get`, `/ask/debug`, `/ask/static/sse_demo.html` all pass a smoke regression test unchanged.

### Data Contract

**Request — `POST /chat/stream` and `POST /chat/debug`**

```
{
  "session_id": string (uuid, required; client mints on New Chat),
  "messages": [                        # full conversation so far, including new user turn as last entry
    { "role": "user" | "assistant", "content": string }
  ],
  "retrieval_mode": "rewrite" | "raw", # default "rewrite"
  "collection": string,
  "store_path": string,
  "embed_model": string,
  "gen_model": string,
  "guardrail": "infer" | "strict" | "topics" | "infer_topics",
  "k": int, "num_ctx": int, "max_context_chars": int,
  "sim_threshold": float | null,
  "use_cfd": bool, "cfd_m": int, "cfd_min_sim": float, "cfd_term_min_sim": float,
  "bundle_topics": bool, "observe_enabled": bool, "observe_async": bool,
  "max_tokens": int,
  "temperature": float | null, "top_p": float | null, "repeat_penalty": float | null,
  "gen_num_ctx": int | null, "seed": int | null, "keep_alive": string | null,
  "include_peek": bool, "include_cfd": bool, "debug_chunks": bool,
  "show_prompt": bool, "show_scores": bool, "trace": bool
}
```

**Response — `POST /chat/stream`** (SSE over `text/event-stream`)

Event names and payloads:

- `event: meta` — `{session_id, turn_index, collection, gen_model, retrieval_mode, k, num_ctx, timings: {...}}`
- `event: rewrite` — `{original, rewrite}` (only when `retrieval_mode="rewrite"` and used)
- `event: sources` — `{items: [{id, score, text_preview, metadata}]}` (populated from retrieval; always emitted, even empty)
- `event: prompt` — `{len, system_preview, messages_preview}` (only if `show_prompt=true`)
- `event: debug` — `{chunks, scores, cfd, trace, ...}` (gated by the same flags as sse_demo)
- default `message` events — streamed token chunks of the assistant's reply
- `event: warn` — finish-reason warnings, empty output, etc.
- `event: done` — `{session_id, turn_index, finish_reason, total_tokens}`

**Response — `POST /chat/debug`** (JSON, non-stream)

Single object mirroring the current `/ask/debug` shape plus `session_id`, `turn_index`, and (when applicable) `rewrite`.

**Client persistence — `localStorage`**

```
key "cfd.chat.index" = [
  { session_id, title, updated_at, created_at }
]
key "cfd.chat.<session_id>" = {
  session_id, title, created_at, updated_at,
  settings: {...},                       # per-chat snapshot
  messages: [{role, content, meta?}]    # meta carries sources/debug per turn
}
```

**Server persistence (CFD)** — Each turn calls the existing `write_observations` behavior. The only addition: every observation's `tags` list includes `session_id:<uuid>`. No other change to the observation schema.

**Update behavior** — Streamed (SSE) for `/chat/stream`; one-shot JSON for `/chat/debug`. No polling, no websockets, no server push outside an active request.

### UI Spec

**Location.** New route `/chat` serving `rag_app/static/chat.html`. HTML is served by a new FastAPI route registered by the chat subpackage (`GET /chat` returns the static HTML; no Jinja).

**Layout.**

```
+----------------------------------------------------------+
| Header: Home | Chat | (links to RAG Admin, CFD Admin…)   |
+-----------+----------------------------------------------+
|           |  Chat Title (editable)        [⚙ Settings]   |
|  Sidebar  +----------------------------------------------+
|           |                                              |
|  [+ New]  |      Transcript (bubbles, scrollable)        |
|           |                                              |
|  - Chat 1 |      [user bubble — right]                   |
|  - Chat 2 |      [assistant bubble — left]               |
|  * Chat 3 |         ▸ Sources   ▸ Debug                  |
|           |         [Copy] [Regenerate]                  |
|  (active) |                                              |
|           +----------------------------------------------+
|           |  Composer: textarea   [Stop] [Send]          |
+-----------+----------------------------------------------+
```

**States.**

- **Empty** (no chats): sidebar shows only "+ New Chat"; main pane shows a centered "Start a new chat" CTA.
- **New chat, no messages**: composer enabled, transcript empty, placeholder "Ask a question…".
- **Streaming**: Send disabled, Stop enabled, status pill "Streaming", new assistant bubble grows token-by-token, Sources/Debug populate as events arrive.
- **Idle (has transcript)**: Send enabled, Stop disabled, composer focused.
- **Error**: assistant bubble shows error text in a distinct style, Retry button replaces Regenerate for that turn.
- **Switching chat**: transcript swap is instant (from `localStorage`); no loading spinner needed.

**Interactions.**

- **Send**: appends user message to local state, persists to localStorage, kicks off `POST /chat/stream`, streams into a new assistant bubble.
- **Stop**: aborts in-flight fetch via `AbortController`; current assistant bubble keeps whatever tokens arrived; turn marked `finish_reason: "aborted"`.
- **Copy**: copies assistant `content` to clipboard.
- **Regenerate**: removes last assistant turn from local state; re-issues `POST /chat/stream` with history ending on the user turn.
- **New Chat**: `window.confirm("Start a new chat? Current chat stays saved.")` → on confirm, mint new `session_id` (uuid v4), push to sidebar, clear transcript, reset composer.
- **Switch chat**: click sidebar item → load that chat from localStorage, restore messages and settings.
- **Rename chat**: click title to edit inline → save on blur/Enter.
- **Settings change**: writes to active chat's settings object; persisted on the next turn (or immediately on blur).

**Responsive.** Desktop-first, parity with sse_demo. Below 768px the sidebar collapses behind a hamburger button. No mobile-specific optimizations beyond that.

**Accessibility.** `aria-live="polite"` on the streaming assistant bubble. Keyboard: Enter sends, Shift+Enter newline, Esc cancels in-flight.

### Component Breakdown

**Backend — new subpackage `rag_app/api/chat/`**

- `__init__.py` — exports the FastAPI router.
- `routes.py` — declares `GET /chat` (serves HTML), `POST /chat/stream`, `POST /chat/debug`. Thin; delegates to `service`.
- `schemas.py` — Pydantic models: `ChatRequest`, `ChatMessage`, `ChatMetaEvent`, `ChatRewriteEvent`, `ChatSourcesEvent`, `ChatDoneEvent`.
- `service.py` — orchestration per request: build effective query → retrieve → build messages[] → stream chat → emit events → write observations.
- `query_rewriter.py` — `rewrite_query(messages, gen_model) -> str`; short deterministic prompt, low max_tokens, no streaming. Returns original question if rewrite fails.
- `history.py` — `trim_history(messages, budget_chars) -> messages`; token-budget-aware sliding trim; never drops the system or the latest user turn.
- `session.py` — helpers for stamping `session_id:<uuid>` into CFD observation tags; wraps the existing `write_observations`.
- `ollama_chat.py` — adapter around Ollama `/api/chat` streaming; mirrors the structure of the existing ollama_generator but sends `messages[]`. Independent from the existing generator module to satisfy Rule Zero.
- `guardrail_adapter.py` — converts a guardrail mode into a system-message string by calling the existing `get_guardrail(mode)` in a read-only way. No edits to the guardrails package.
- Router must be mounted in the FastAPI app only if it does not clash with existing `/ask` routes. Mount point: main app file (existing) — a single `app.include_router(chat_router)` line, additive.

**Frontend — new directory `rag_app/static/chat/`**

- `chat.html` (lives at `rag_app/static/chat.html` so `/chat` can serve it directly).
- `chat.css` — styles for bubbles, sidebar, composer. Independent from `sse_demo.css`.
- `chat.js` — entry module: wires DOM, imports from the `chat/` submodules.
- `chat/state.js` — chat-list + active-chat store; read/write to localStorage; pub-sub for UI updates.
- `chat/session.js` — session_id minting (uuid v4), chat creation/rename/delete.
- `chat/api.js` — `streamChat(payload, {onMeta, onRewrite, onSources, onToken, onDebug, onDone, onWarn, signal})`; wraps fetch + SSE parsing for `POST /chat/stream`. Also `fetchDebug(payload)`.
- `chat/sse_parser.js` — generic text/event-stream line parser (so `api.js` stays focused).
- `chat/renderer.js` — renders transcript, bubbles, sidebar items, sources/debug collapsibles. Imports a local markdown function (duplicated from sse_markdown.js, NOT imported — Rule Zero).
- `chat/markdown.js` — self-contained markdown renderer duplicated from [sse_markdown.js](vscode-webview://0lo17r9qvsne1l55u4vdg1vj0bd22tkf6p0vs3rke2vaf47agvr8/rag_app/static/sse_markdown.js).
- `chat/settings.js` — settings panel controller; reads/writes active-chat settings in `state.js`.
- `chat/composer.js` — textarea, Send/Stop, keyboard handlers, abort controller wiring.
- `chat/sidebar.js` — chat list, New Chat button + confirm, switch/rename.

Every file is `<script type="module">` or imported from `chat.js`. No bundler. One-responsibility-per-file.

### Out of Scope

- Edit-a-prior-user-turn and delete-a-turn actions (phase 2).
- Rolling LLM summarization of old turns (phase 2; current trim is token-budget sliding).
- Server-side resume-by-session-id endpoint (localStorage is sufficient for MVP; server has the data via CFD for later retrieval).
- Multi-user auth / per-user chat isolation (localStorage is per-browser; no auth layer added).
- Refactoring sse_demo to share modules with the chat page.
- Exporting transcripts (JSON/Markdown download).
- Voice input, file uploads, image input.
- A separate "Chat" entry in the header of sse_demo.html **unless the user explicitly approves** that modification — see Open Questions.
- Migration of existing CFD observations to add session_ids retroactively.
- Streaming the rewrite step token-by-token (rewrite is a blocking sub-call).

### Open Questions

1. **sse_demo.html header nav link to `/chat`.** Adding one link is a two-line edit, but Rule Zero says nothing existing changes. Confirm: add the link (cheap, low-risk), or leave sse_demo untouched and surface `/chat` only from Home?
2. **FastAPI app mount point.** The subpackage exports a router; the main app file needs one `include_router` line. Confirm which file that is, or flag as a one-line integration task for the implementer.
3. **Static-file serving.** Currently sse_demo is served under `/ask/static/*`. `/chat` needs either its own StaticFiles mount or an explicit `GET /chat` FileResponse route. Implementer picks based on existing app conventions.
4. **Token-budget constant.** History trim threshold — use `gen_num_ctx - max_tokens - est_context_chars/4` as char budget, with a floor default of 6000 chars if `gen_num_ctx` isn't set. Confirm or provide a specific budget.
5. **Chat title auto-generation.** Default new-chat title is "New Chat YYYY-MM-DD HH:MM". Option: run a one-shot LLM title generation after the first turn (adds one call). Default: no auto-title; user renames if they want.
6. **Regenerate when there are no prior turns.** Button is hidden on the first user turn (nothing to regenerate yet); reappears after first assistant reply. Confirm.
7. **CFD observation on aborted turn.** If Stop is hit mid-stream, do we still write observations for the partial assistant output? Default: no — aborted turns are not persisted to CFD, only to localStorage.
8. **Concurrent chats.** Only one chat can stream at a time per browser tab (active chat). Switching chats while one is streaming aborts the in-flight request. Confirm.
